# Промпт инициализации проекта для Claude Code

Скопируйте содержимое блока ниже целиком в новую сессию Claude Code.

---

```text
Ты — Claude Code, агент разработки. Это стартовая сессия инициализации проекта.

## Цель сессии

1. Проинициализировать рабочую папку проекта для Claude Code.
2. Подключить репозиторий к моему аккаунту GitHub (авторизация — через вопросы ко мне, ничего не угадывай).
3. Настроить рабочий процесс: задания приходят из папки `.tasks/` (она в `.gitignore`), ты реализуешь их и синхронизируешь результат с GitHub.

## Шаги, которые нужно выполнить сейчас

### 1. Контекст рабочей директории

- Определи текущую директорию (`pwd`).
- Если это ещё не git-репозиторий — подготовь инициализацию, но **не** делай `git init` и не создавай remote, пока я не подтвержу имя репозитория и видимость (public/private).
- Если репозиторий уже есть — покажи `git remote -v` и текущую ветку.

### 2. Авторизация GitHub

Задай мне вопросы и дождись ответов. Ничего не предполагай сам:

1. Использовать уже настроенный `gh auth` на этой машине или войти заново?
2. Имя пользователя / организации GitHub для репозитория?
3. Имя репозитория?
4. Public или private?
5. Предпочтительный способ аутентификации: `gh auth login` (HTTPS/SSH) или уже есть SSH-ключ / token?
6. Нужно ли создать новый репозиторий через `gh repo create` или подключить существующий?

После моих ответов:

- выполни авторизацию / проверку (`gh auth status`);
- создай или привяжи remote;
- сделай первый commit и push только после моего явного подтверждения.

### 3. Структура проекта для Claude Code

Создай (если ещё нет) минимальный каркас:

- `CLAUDE.md` — краткие правила работы агента над этим проектом (язык, стиль коммитов, как брать задачи из `.tasks`, как синхронизировать с GitHub).
- `.gitignore` — обязательно включи:
  - `.tasks/`
  - `.env`, `.env.*`
  - типичный мусор редакторов/ОС и кэши
- `.tasks/` — локальная папка заданий (не в git).
- Шаблон задания вынеси в `docs/task-template.md` (этот файл уже в git). Локальные файлы в `.tasks/` не коммитить.

Формат файла задания в `.tasks/` (ориентир):

# TASK-XXX — краткий заголовок

## Статус
todo | in_progress | done

## Цель
...

## Требования
- ...

## Критерии приёмки
- ...

## Заметки
...

### 4. Правила дальнейшей работы (зафиксируй в CLAUDE.md)

- Новые задания я кладу в `.tasks/` или указываю файл явно.
- Ты читаешь задание, реализуешь его в коде, пишешь/обновляешь тесты при необходимости.
- После завершения задания:
  1. обновляешь статус в файле задания на `done` (локально);
  2. делаешь осмысленный commit;
  3. пушишь в GitHub;
  4. кратко отчитываешься: что сделано, какие файлы изменены, хеш коммита.
- Папку `.tasks/` никогда не коммить и не пушь.
- Не коммить секреты, ключи, `.env`.
- Перед деструктивными действиями (force push, удаление веток, `reset --hard`) — спрашивай подтверждение.

### 5. Завершение инициализации

В конце этой сессии выдай отчёт:

- путь проекта;
- статус git (branch, remote);
- статус `gh auth`;
- что создано/изменено;
- готовность принимать первое задание из `.tasks/`.

## Ограничения

- Не выдумывай GitHub credentials и не подставляй чужие данные.
- Не пушь, пока я явно не подтвержу remote и первый commit.
- Работай последовательно: сначала вопросы по GitHub, потом инициализация, потом подтверждение.

Начни с шага 1 и блока вопросов из шага 2.
```

---

## Как использовать

1. Откройте нужную папку проекта в терминале.
2. Запустите Claude Code.
3. Вставьте текст из блока `text` выше.
4. Ответьте на вопросы про GitHub.
5. После инициализации кладите ТЗ в `.tasks/` (например `.tasks/TASK-001.md`) и пишите агенту: «Выполни `.tasks/TASK-001.md`».
